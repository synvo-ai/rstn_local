Workflow and architecture

Solved, shown in POC Solved, needs NTU data source Partly solved New build RSTN scope LLMmodel call, billed per token rulesdeterministic, near-zero cost
  • RSTN calls the engine once per email and gets one result back. Staff changing a treatment triggers a second, smaller call that re-checks only that issue.
  • Only steps 3 and 7 always call a model; step 2 runs only with attachments, step 4 only when the programme is unclear, and steps 1, 5, 6 are pure rules. That is why the unit cost is low and predictable: about four model calls per email in the POC (understand ~1.5k tokens, programme ~0.7k when ambiguous, draft + verify ~3.8k).
  • If the engine fails, RSTN sends its static acknowledgement and queues the email for staff. A failed run never reaches the enquirer as an answer.
  • Historical emails become approved, citable knowledge after curation and NTU sign-off. We do not train a model on them.

Unit cost formula for the 1-pager

cost per email = Σ stages ( calls × (input tokens × input price + output tokens × output price) )
               + attachment share × reading cost (OCR or vision)
               + retrieval cost per query (embeddings, search)
               + (hosting + monitoring per month) ÷ emails per month

fixed, priced separately = integration build · historical curation · evaluation · support · phase 2
Before quoting a price: re-price the token counts at today's provider rates, then run the engine beside the live inbox for 1–2 weeks with nothing sent, and report cost and latency per email by type (simple, multi-question, follow-up, with attachment). If NTU requires models to run on-prem, the variable cost becomes GPU amortisation and has to be quoted as a separate line.

What moves the number

  • Where models may run (open with RSTN). Cloud model API: cost scales per email. On-prem GPU: mostly fixed cost, higher at this volume.
  • Size of retrieved evidence. Real NTU pages and historical answers are larger than the POC store. Capping evidence per issue keeps draft and verify in check.
  • Screenshots. OCR adds little. Vision adds roughly one extra model call per attachment. We need sample screenshots to choose.
  • Model choice per stage. Through the model gateway, simple stages can use a cheaper model without touching business rules. In Round A, Luna was the cheapest and also scored highest in blind review (18.5 of 21).
